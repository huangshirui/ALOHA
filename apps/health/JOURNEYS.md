# ALOHA Health · 第一批用户旅程与交互契约（UX Prototype）

> **决策：以用户目的为入口，而非七张模型管理表。** 当前原型只有虚构数据，所有操作仅在本次浏览器页面内存中生效。该文件约束交互，不修改 LifeSpace Health Schema。

## 先回答用户的六个问题

| 编号 / 旅程 | 用户问题 / 触发场景 | 起点 → 决策 → 操作 → 完成反馈 |
| --- | --- | --- |
| J1 快速记录 | “刚测过一次，想记下来” | **首页「快速记录」/ 时间线「新增记录」** → 选择测量/事件/评估 → 只填写对应必填项、可关联健康问题/资料 → 保存 → **刚创建的记录详情** → 返回起点 |
| J2 持续关注 | “一个健康问题最近怎么样？” | **身体·概览人体图 → 点击部位 → 查看该部位的 HealthConcern 列表 → 点击问题 → 详情与相关数据**；也可从首页关注事项直达详情 → 从对应区块添加测量/事件/方案/资料/评估 → **返回原关注事项** |
| J3 指标趋势 | “血压最近有什么变化？” | 身体·指标 → 选指标 → 最近结果 / 趋势 / 历史 → 选某次记录查看原始来源，或「记录一次」（已带入当前指标与单位） → 保存 → 新记录详情 → **返回当前指标详情** |
| J4 整理资料 | “拿到报告，放哪里？” | 身体·资料 / Concern 依据区 → 添加资料 → 选择本地文件名（无读取、无上传） → 虚构提取预览 → 用户明确勾选是否添加模拟测量 → 确认 → **资料详情** → 查看关联模拟观测与原健康问题 → 返回原页面 |
| J5 干预与方案 | “这段时间有什么计划？” | 健康问题 / 身体·干预 → 新建方案 → 填写内容、周期和日期 → 保存 → 方案详情 → 首页演示完成状态 / 回顾相关问题。实际 Task 与 Recurrence 尚未接入 |
| J6 按时间回顾 | “几周前发生了什么？” | 身体·时间线 → 按时间浏览/搜索 → 查看测量、健康事件、评估 → 追溯来源资料、所属关注事项和评估依据 → **返回原时间线**继续浏览 |

## 交互动作唯一性 / One Primary Action per Screen

| 当前页面 | 顶部唯一的新增动作 | 附近允许的次级操作 |
| --- | --- | --- |
| 首页 | **快速记录** → 测量 / 事件 / 评估三选一 | 查看关注事项、指标、全部资料；不在同一页额外复制快捷新增按钮 |
| 身体·概览 | **添加健康问题** | 选择人体标记 → 该部位的健康问题列表 → HealthConcern 详情；未标记的关注事项可以关联身体部位 |
| 身体·健康问题 | **添加健康问题** | 列表搜索 |
| 身体·指标 | **新增指标**（定义指标类型） | 进入指标详情后才出现「记录一次」 |
| 身体·时间线 | **新增记录** → 测量 / 事件 / 评估 | 搜索记录；不再有“记一件事”和并列的三种快捷新增 |
| 身体·资料 | **添加资料** → 导入与核对 | 搜索已保存的资料 |
| 身体·干预 | **新建方案** | 搜索方案 |
| 具体记录详情 | **修改**（不是第二个全局新增） | 删除；关联卡片有各自明确的「添加测量 / 添加事件 / 添加资料 / 添加方案」等 |
| 指标详情 | **记录一次** | 查看历史数值和单次记录 |
| 健康问题详情 | 不再有含糊的“新增记录”总按钮 | 对应卡片直接新增对应对象，自动关联当前健康问题 |

**规则：** 顶部 Contextual Action 由当前 Tab 决定。下方搜索区**只负责筛选**，不再复制创建入口。不同目标的卡片内按钮可以保留，但必须具备明确的对象和上下文；UI 元素数量不是目标，避免重复和意外跳转才是目标。

## 首页与身体概览的边界

- **ALOHA Health 首页**是时间与行动维度：近期变化、正在关注、重点指标、今天的方案和快速记录。
- **身体 → 概览**是空间维度：使用无性别、正面的简洁线框人体图（细线、不填充、不画内部器官），在位置上标记关联 HealthConcern 的部位。右侧按行动优先级安排卡片：**所选部位的问题及状态 → 其他有关注事项的部位快捷切换 → 尚未标记部位的问题及人工关联**。不再展示重复的纯数量分布统计卡，更不复制首页的指标趋势、任务或最近事件。
- 身体图中点击区域先显示这个部位的 HealthConcern 名单。同部位多个问题先列出来再进入，不能直接跳入某个未指定优先级的记录。选中问题后进入 Concern 详情，之后才向下进入 Observation、Document、Event、Assessment、Regimen。
- **BodyMapRegion 与 BodyMapBinding 属于 ALOHA 应用侧的展示投影**，绝不作为第一批 LifeSpace HealthConcern Schema 字段；原型以本地映射数据演示（c-1 对应胸部、c-2 对应下肢），都是虚构实例，不代表医疗判断。新增未定位的问题保持可见，并可在右侧明确手动指定部位；不自动按名称推断。
- 无绑定标记只是“暂无关联健康问题”，不代表身体无异常或不存在健康风险。初始原型没有账号、真实授权及持久化。

## 身体地图坐标、标记与点击确认（BodyMap v1）

- **素材是独立文件**：`public/body-front-outline.svg` 使用正面无性别细线人体线稿，独立 `viewBox=340×520`。在页面仅按固定宽高比 `object-fit:contain` 等比缩放，不再用 `transform(scale(-1,1))` 拼接肢体。界面不重复「从身体部位探索 / 身体健康图 / 点击标记」三段顶端说明，只保留「身体图」。
- **可见问题点**：有正在关注事项的部位只显示一个直径约 8px 的绿色小圆点。鼠标悬停/键盘焦点显示双层光晕；移动端没有 Hover，点击后的已选中部位保留较小的持续光晕。命中区约 42px，不因视觉点小而难点。区域里若有多个 HealthConcern，在右侧列表分别显示，人体图仍只显示一个聚合点。
- **位置 map**：`body-map.ts` 保存图片版本 `BODY_MAP_ASSET_ID`、区域及默认锚点（归一化 `[0,1]` 坐标）；关联 `BodyMapBinding` 可选指定 `assetId + point{x,y}`，避免在图片缩放/布局变化时漂移。更换基础线稿时必须同时审校/迁移锚点，不让旧位置悄悄指向新素材错误部位。
- **绑定旅程**：右侧未定位/已定位关注事项 → 「在身体图上点选位置 / 调整标记位置」 → 在人体图上点一下 → 看到小圆点及光晕预览 → **确认位置**才保存到演示状态。仍可在下拉框直接选择大部位，使用默认锚点。关联属于 ALOHA 展示投影，不修改 HealthConcern Schema；暂不自动按病名推断位置或提供医疗判断。
- **窄屏旅程**：人体图上点已标记的圆点后，自动滚动至下方对应区域卡片；右侧 AI 打开时若宽度不足，图上卡下。所有操作保留本地演示状态，刷新重置，不承诺真实持久化。

## 保存、返回、取消与来源

- **保存后**：显示刚创建的对象的详情，能立即核对内容和关联，而不是一律跳回时间线。
- **返回**：使用本次浏览的原始位置。首页 → 关注事项 → 相关观测时，返回应先回到关注事项，再回首页。指标详情 → 测量也是同样规则。
- **编辑原记录**：保存后留在同一记录详情，不产生多余历史记录。
- **取消**：关闭表单，原页面、滚动内容和已展开的 AI 对话不被重置。
- **失败**：表单保留已填写的信息，直接给出缺项或日期规则；允许修正后再次提交。
- **数据关联**：HealthConcern / 证据来源是显式选择，不能因为访问过某页面就自动把不相关记录绑定过去。只有在某个健康问题的「添加」入口中才预填该关联。
- **删除**：原型解除关联而不级联删除健康事实；已有观测的指标禁止删除或改值类型。

## 七个领域模型与用户任务的边界

- **HealthConcern**：纵向专题，容纳关联关系，不拥有/复制原始健康事实。
- **HealthMetric**：指标定义，创建一次、可持续复用。
- **HealthObservation**：一次按类型（数字/文本/是-否）录入的原始结果；来源可以是手工或报告。
- **HealthEvent**：发生过什么，时间轴上的事实。
- **HealthDocument**：保留原报告的证据入口；演示只保存文件名。
- **HealthAssessment**：有日期和依据的判断/评估，独立于原始结果。
- **HealthRegimen**：持续方案；执行任务由后续平台机制处理，不在 Health 浏览器内自建定时服务。

## 验收顺序

1. Desktop 1440px：J1→J2→J3→J4→J5→J6，从新增、详情、返回逐条检查。
2. Mobile 375px / 430px：相同六条路径，检查底部菜单、类型选择菜单、输入抽屉和所填数据不会因转场丢失。
3. Tablet 768px / Desktop 1024px：聊天侧栏打开时，浏览及返回路径保持一致。
4. 数据检查：所有文件均未被读取或上传；刷新后演示数据还原；观察值互斥、来源引用与用户确认显式；不包含真实医学结论。

**后端留白：** 真正的 Health File 生命周期、身份/Space/Grant、Semantic Relation、Recurring Task、Agent 对话/操作确认，仍需 LifeSpace/ALOHA 对应可信服务支持。本原型不得暗示已部署这些能力。
