# ALOHA Health · UX 体验原型

> 仅供体验和评审。所有启动数据均为虚构示例；新增内容只保存在当前页面内存中，刷新即恢复。不接入 LifeSpace、真实 AI 或任何健康数据接口。

## 时间轴式「时间线」（2026-10-28）

- 时间线从扁平列表调整为按年/月、日分组的**纵向时间轴**，左日期栏、中央连接线/小节点、右轻量记录行；同日多条测量、事件和评估在同一日期组下，不重复日期标题。
- 顶部保留原有搜索框和唯一「新增记录」菜单；时间线只提供「全部、测量、事件、评估」筛选。记录来自现有 HealthObservation/HealthEvent/HealthAssessment，发生日期由原记录提供，健康事件若明确填写开始时间才显示 HH:mm；不制造未存储的时刻。未填写或无效日期收进「未填写日期」末尾组。
- 每条时间轴记录点开仍使用原记录详情与返回栈；用户从详情返回时恢复关键词、类型筛选和时间轴滚动位置。新建或编辑之后自动反映，不建立重复的「时间线记录」模型。
- Desktop、Mobile 和打开 Agent 缩小的容器下均按现有 Token 紧凑展示；节点只用微弱 Health 绿，不是关注度、疾病严重程度或医学预警。原型仍只包含虚构数据。

## 2026-10-28 · 指标趋势图宽、高和刻度可读性

- **用户反馈**：指标详情中的趋势图还不够宽，高度过矮，坐标轴刻度过小。宽屏趋势区扩大（趋势/历史列宽由约 61%/39% 调为约 69%/31%，历史仍保留至少 16rem）；Agent 侧栏打开时优先将趋势与历史上下排列，不强制挤出窄小双栏。
- **真实绘图区**：趋势 SVG 逻辑高度由 224px 增至 **320px**，Y 轴刻度字号由 12px 改为 **14.5px**。使用 ResizeObserver 测量图表的**实际容器宽度**后同步计算 SVG viewBox、轴线、时间轴刻度与观测点，不通过整体缩小固定 680px SVG 的方式损失字体可读性。
- **响应式**：窄内容区域（含 Mobile / AI 展开）基于真实宽度缩减 X 轴标签数量：不到 440px 最多 3 个、440–619px 最多 4 个、其余最多 5 个，避免日期碰撞。首次无数据后新建观测，也应在图表出现时重新绑定尺寸观察。
- **不改语义**：日／月／年切换、缺失周期只连线不造数值、点选查看真实来源等逻辑保持原样；仅针对视觉尺寸和阅读密度优化。本轮不调整 LifeSpace Schema、不引入第三方图表依赖。

## 2026-10-28 · 指标详情 UX 重排（最新 → 趋势 → 历史）

- 用户打开指标只需依次完成三件事：确认最新数值与具体日期 → 看长期变化 → 找到并打开某条历史记录。主卡片「变化趋势」标题右侧删除重复单位；日/月/年控制旁也不重复单位。
- 最新 KPI 只显示一处数值和单位，日期显示为「最新记录 · YYYY.MM.DD」。趋势 SVG 默认无所选点，取消原先进入页面就展示另一条历史读数的误导性重复区块；仅在主动点击真实节点时出现紧凑说明条（标注「已选」），单次可进原始记录，多次则明确为平均值及真实记录数。可取消，切换粒度清空。
- 历史记录列表显示真实记录及总条数，宽屏为趋势区域多分配空间，历史卡片只占内容高度；Mobile/AI 窄布局叠放。保留统一的「记录一次」主操作。
- 仅调整 ALOHA Health 展示；聚合与缺失记录连线规则保持原样。不添加 LifeSpace 模型字段和真实健康数据。

## 2026-10-28 · 指标筛选与儿童生长曲线设计边界

- 「身体 → 指标」不只有搜索：增加「全部、范围内、超出范围、未判定」四个状态过滤，使用**最近一条有效观测**和适用参考上下限比较，筛选数量实时随新增/编辑后的虚构数据更新。现有单位不同、无参考来源和无数值记录等无法比较情形归入「未判定」，不能被误归为正常或异常。
- 身高和儿童 BMI 这类随年龄变化指标不能把单个上下限当成长期永久正常标准。后续新增可引用的「年龄／适用人群参考标准」策略：数据集标准 ID+版本、参考曲线种类（身高年龄分位数）、适用年龄与单位、需要的出生日期和仅用于该参考规则的必要个人参数。以**记录当天月龄**匹配参考分位曲线；明确数据来源与版本，并保留当次评估依据，不用今天的年龄回算历史或把分位数高低当作病情诊断。
- 本轮不提交未经验证的儿科生长数据、不自行定义第 N 百分位为异常、不新增 LifeSpace 模型或发布数据。动态参考曲线的规范待单独设计并核对 WHO/CDC/适用地区标准的完整授权与适用条件。

## 2026-10-28 · 越界箭头与轻量参考虚线（用户反馈）

- **信息减法**：用户要求“不正常的不要用文字，而用图标表示高于或低于”。指标列表、最新值和观测历史里，只有对比结果确实是「高于参考」或「低于参考」才显示克制的 Lucide ArrowUp / ArrowDown 小图标；落在范围内、没有范围或单位无法比较时**不显示状态图标**，避免“在参考范围内”文字重复和正常状态占空间。箭头方向表示**相对参考上下限**，不是相对上次观测的升降趋势；Hover title 和 aria-label 保留清晰语义，不能只靠颜色传达。
- **图表参考线**：指标设置了 referenceLow / referenceHigh 时，趋势图在该数值位置画浅暖色、低透明度的细虚线（约 1.25px，短虚线），显示极淡的「下限/上限 + 值」标签。放在真实测量曲线**下层**，真实折线与节点优先。替换上一版背景色块，避免低对比的真实变化被一整块颜色遮挡。单侧范围只画一条线，两端数值相等时只画一条；非法上下限不画。
- **纵轴可见性与数据边界**：纵轴范围容纳实际观测值与已设置的参考上下限，保证可见的虚线位置是**真实数值**；参考边界只影响缩放尺度和图示，不增加观测点，不参与日／月／年平均、历史列表及异常推断。极宽的参考范围可能压缩曲线幅度，先在 Preview 检查图形可辨性，不用错误位置的参考线来换取曲线高度。
- **来源不变**：观测自身范围优先比较；趋势虚线只表示指标默认参考范围（而非混合多份报告），原报告 interpretation 继续在观测详情独立展示。范围比较不等于医学诊断。仅本次虚构 Health 原型 UX，未改 LifeSpace 模型/部署。

## 2026-10-28 · 参考范围对比 UX 与双层 Schema 草案

- 依据用户同意的方案：HealthMetric 增加可选默认参考下限/上限/来源，HealthObservation 增加可选本次报告范围上下限/来源，保留既有 `interpretation` 作为报告自身的解释。
- UI 提供指标表单的可选范围配置、观测录入时的当次范围覆盖；只要当次任一边界存在就只用当次边界，不混搭默认另一侧。上下限顺序校验；单位不一致无转换时不进行高低判断。范围内仅表示落在所设范围之内，**不宣称正常或无风险**。
- 最新观测、趋势图与历史记录均以克制的点/文字或浅色带呈现上下限；原报告的标记在详情中单独展示，不被计算覆盖。未设范围、不适用、单位不同等情况不装作有正常/异常结论。
- 这里的范围是有来源的参考范围，个人目标由 Goal 关联管理，不默认复制到参考范围；无多段年龄/性别标准库，也不做自动危急值推断。
- 这轮只有 ALOHA 虚构原型及 Notion **待 Validate 的** Schema 草案，未更改 LifeSpace 代码或发布数据模型。

## 「指标 → 观测趋势」年／月／日（2026-10-28）

- 详情页数值趋势新增「日／月／年」切换：自然日/月/年的有效数字观测**按周期算术平均**，图上点显示该周期均值和真实记录数量，只有一条观测时可进入其原始详情。
- 横坐标是实际日期间距，而不是简单等分记录索引；若中间几天、几个月或几年没有观测，允许一条连续、非过冲的平滑线从前一个真实观测点连到后一个点，**不补零、不插入假数据点、不把中间曲线解释成实际值**。只有一条记录则只有一个点，不绘制虚构趋势。
- 只对数值 HealthMetric 展示曲线，排除录入错误/无效观测以及缺失或异常日期。文字/是或否结果继续在历史记录查看，不强行作数值趋势。
- 配合统一 Health 语义 Token 和既有指标详情，不增加重复的主「新增」操作；历史记录、单点来源和返回路径不变。仅修改 ALOHA UX 原型，尚未连接 LifeSpace 数据接口。

## 体验目标

使用 ALOHA 统一视觉语言，让普通用户以“健康问题、指标、记录、资料和方案”为入口完成一系列具体操作，而不是在首页查看一组静态卡片。

## 从用户旅程推进交互（2026-10-27）

**本轮权威 UX 文档：** [JOURNEYS.md](./JOURNEYS.md)。以用户结果为导向的六条主路径：快速记录、持续健康关注、指标趋势、报告整理、方案管理、时间线回顾。

- 每个页面只提供一个与当前上下文相关的主要新增操作：Body Tab 顶部自动切换；首页/时间线使用相同三类型记录菜单；身体的「关注」Tab 将人体图与可搜索的全部健康关注事项合并在一个页面，页级操作仅「添加关注」。
- 移除时间线「记一件事」与并排「测量／事件／评估」重复按钮，也移除原先通用的「添加记录」；搜索区只负责查询。
- 保存后首先展示新记录详情，返回恢复发起操作的首页、关注事项、指标或列表。嵌套来源/证据链接继续使用同一返回栈。
- 资料流程选择虚构文件名→核对独立模拟提取→确认→资料详情可查看关联观测/事件；报告内容从未被读取或上传。
- 保留 HealthConcern 专题内不同对象的明确快捷动作，因为它们代表不同用户目标，不是复制同一个按钮。
- 手机/桌面统一的 `HealthPageHeader`、ALOHA Token、Lucide、表单抽屉和右侧常驻 Health Agent 均继续沿用。

## 身体·关注：正背双视图和全量关注列表（2026-10-28）

- Health 首页关注时间与行动；身体「关注」把原「概览」和「健康问题」两个 Tab 合并为一个完整工作区：左侧人体点位导航，右侧始终显示**可搜索的全部关注事项**，包括正面、背面、未定位和已结束事项。不按身体部位分组。
- **独立点位：** `BodyMapBinding={concernId,view:'front'|'back',assetId,point:{x,y}}`。MVP 一项 HealthConcern 一个定位点。每次点击点选中唯一 Concern，右侧完整列表高亮这一项，列表可直接打开详情或调整定位；不汇总成「胸部一个点显示 N 项」。
- **正背面素材与发现：** 原用户 clean 线框作为正面 `body-front-outline.svg`；增加专用 `body-back-outline.svg`，保持 244:475 轮廓比例和原始坐标系不变，使用原创背侧耳廓、去除正面下巴闭合轮廓、肩胛骨弧线及克制的臀线表达背面，不直接描摹带版权水印的参考图；二者的 assetId 分别版本化。图卡宽度不足时显示「正面 N／背面 M」切换；图卡自身宽度达到约 30rem（480px）才双图并排：11.5rem 单图宽、0.75rem 图间距、整体居中，避免原先两个等分网格列将正背图推得很远。开 AI 缩窄内容会自动退回单图切换，Mobile 始终只看一面。
- **网格只在人体外：** 36px 非交互淡网格位于画布底层；人体下方的白色不透明矢量填充遮住轮廓内网格，最上层原 SVG 线稿不改路径、不缩放变形。Preview 观察是否有轮廓边缘网格穿透，不好则删除网格图层。
- **定位旅程：** 右侧每个 Concern 行的 Pin 图标→正/背面→点击人体内部→小点光晕预览→确认。初始浏览点点→右侧选中该问题→进入详情；窄屏时自动滚动至该记录列表。
- **布局：** 桌面内容够宽，线稿左、**全部关注事项**右；打开 AI 后依据实际内容宽度调整；手机一律图上列表下。搜索不影响地图和已有选择，点击地图点会清空筛选以显示对应记录。返回问题详情时保留正背面和已选择的记录。
- **列表选中视觉**：取消选中 Concern 行左侧的绿色竖线，统一使用极淡的无方向性底色与约 1px 的低对比轮廓；不对整张卡片做大块染色。
- **关注度（应用原型状态）：** 关注项新建／编辑表单和详情都可选择「未设置、日常关注、重点关注、优先处理」。前两项为灰/Health 绿，重点为低饱和琥珀，优先为柔和珊瑚红。只改变点、有限半径 Halo 与小文字状态，不染整张卡片；默认 10px 点有浅光晕，选中点约 3 秒轻缓呼吸；`prefers-reduced-motion` 停止动画。明确是用户自选优先级，非医学严重度，无自动诊断或预警。关注度没有添加到 LifeSpace HealthConcern 字段，只存演示浏览器状态。
- **边界：** 不修改 LifeSpace 健康模型。已新增背面独立素材；一个 Concern 多位置、多个点完全重合的可视化仍留待真实使用证据后再处理。原型始终没有真实个人健康数据。

## ALOHA 更多：整页导航（2026-10-28）

- Mobile 底部五 Tab 为「首页／身体／饮食／运动／更多（LayoutGrid）」，**更多与其他 Tab 同样是页面**，内部展示应用切换、账号与安全、授权、通用设置、帮助；无弹窗、无遮罩，切到其他 Tab 再回来按普通页面导航。
- Desktop 左侧 ALOHA Logo 点击也进入同一个完整「更多」页，避免 Desktop 和 Mobile 维持两套内容；Desktop 左侧导航保留四个领域入口，不另加第五个重复导航项。
- `AlohaHub.vue` 复用同一份功能区内容，可配置 `page` 模式。Mobile 子页 Header 不显示 ALOHA 标志，返回箭头只出现一个；Agent 对话不因切页关闭。

## Mobile 顶部、滚动及表单一致性验收（2026-10-27）

- **顶部排布：** 统一 `HealthPageHeader.vue` 负责移动端 ALOHA Hub、当前标题、主要操作与 Lucide AI 入口，**始终单行**；手机隐藏冗余副标题，AI 用图标按钮保留可访问名称。标题过长时用省略号，不能挤出第二行按钮。
- **滚动：** Desktop 与 Mobile 的正文正常滚动；唯一紧凑工具栏采用 `position: sticky`。**在页面顶端工具栏背景透明，与内容画布融为一体；滚动超过 8px 后才显示基于 Canvas Token 的轻磨砂背景和细分隔线**，避免在淡色渐变画布上出现突兀的白色矩形。底部主导航和独立 Agent 面板继续保持可操作。
- **抽屉轮廓：** Desktop 右侧表单 Drawer 为直角边缘；Mobile/窄平板底部表单和 AI 停靠栏使用一致的顶部双圆角，带自身滚动区；普通表单仍带遮罩，AI 始终非模态。
- **下拉框：** 所有 Health `select` 使用统一的 Lucide ChevronDown 图形、`appearance:none` 和不小于 2.85rem 的右侧文本空间；在 iOS Safari、Android Chrome、Desktop Chrome 验证箭头不贴边、长文本不覆盖箭头。
- **必填标志：** 必填号包在和字段名同一行的 `field-label` 内，保持正确视觉对齐；这是之前 `label` 纵向 Flex 把子元素 `*` 排成另一行的根因，不允许在新表单中再直接放裸 `<span>*</span>`。
- **回归场景：** 375px、430px、768px、1024px、1440px 五个宽度，检查首页/身体指标/健康问题详情、含下拉框的测量新增抽屉、AI 打开后的空间与滚动。此项需在重新部署 Preview 后人工验收，不能仅凭 CI 宣称视觉已通过。

## 统一页面密度与字体（2026-10-27）

- 所有 Health 页面共享 `apps/health/src/components/HealthPageHeader.vue`。首页、身体页、所有七模型详情，以及饮食/运动一级入口统一使用**同一个标题 / 返回 / 页面操作 / AI 按钮结构**；不再在每页创建自己的 Header。
- 以“身体健康”为例：标题保持约 22px，下面只有简短的一行说明；页内导航紧贴标题区。移除此前冗长的“从记录到理解”大标题段落，减少顶部空白，尽快露出搜索与实际记录。
- 跨应用字体角色在 `packages/design-tokens/tokens.css`，包含辅助说明、控件、正文、模块标题、页面标题与关键数字的固定层级，规范见 `docs/design-system.md`。
- Health 通过 `apps/health/src/tokens.css` 映射上述全局角色及列表高度、卡片间距和页面节奏；`apps/health/src/ui-system.css` 把同一套规则应用于所有列表、卡片、指标、表单和子导航，而不是各个页面私有缩放。
- 现有 `style.css` 仍负责页面布局、抽屉和响应式分栏；UI System 文件作为统一字号/间距表现层。Hub 中的舒适/紧凑只更改密度 Token，不破坏核心字号和触控目标。
- Health 原型的字体/密度体系已经实现，但其他 PWA 是否采用相同页面组件，应由各自实际 UX 验证决定；全局字体 Token 会自动可供所有 Surface 使用。
- 此轮不包含真实生命体征或个人健康记录，仍为可公开的虚构演示数据。

## 统一导航和 ALOHA 公共入口（2026-10-27）

1. **可折叠的左侧导航**：桌面侧栏有完整文字导航与仅图标窄栏两种状态，可即时切换；图标模式提供 tooltip / accessible label，内容区和常驻 Agent 会随侧栏宽度自动调整。窄屏使用底部导航，不强行显示桌面窄栏。
2. **标题与操作合并**：移除在桌面内容区上方另起一层的固定 Health Header。每个页面的唯一标题区同时包含当前页面名称、页面相关的新增/修改/删除操作，以及始终可用的“问问 Health”入口；在详情页也不引入重复品牌标题。Agent 会话仍独立于页面路由。
3. **唯一 ALOHA 公共入口**：只有左侧顶部 ALOHA（移动端放在当前页标题中）打开统一的应用 / 账号 / 设置菜单，内容区不再复制同一个应用切换按钮。
4. **公共入口的初始内容**：应用切换（Assistant / Health / Finance / Things）、账号与安全（个人资料、登录方式及设备）、隐私与授权（应用及人员数据授权）、通用设置（外观和语言、通知与提醒、实际可交互的“舒适 / 紧凑”页面密度）、帮助与反馈（帮助、关于）。除当前 Health 和页面密度外，原型对尚未接入的功能明确标记，不创建假链接或假登录态。
5. **可复用性策略**：公共菜单实现为可通过 `currentApp`、`apps`、`density`、`preview` 配置的 AlohaHub Vue 组件，目前先由 Health 使用，放在 `apps/health/src/components/AlohaHub.vue`。按仓库 `packages/ui/AGENTS.md`，只有第二个真实应用消费且交互契约稳定后，才将其提升到 `@aloha/ui` 共享包；不为了展示“共享”去污染其它应用空骨架。
6. **当前状态**：只是本地无身份的 UX 原型，公共账号/授权/通知不会执行真实操作。真实项目应复用 LifeSpace Identity、Space/Grant 和 ALOHA 公共配置，不在 Health 内自建独立账户系统。

## Health Agent 的双栏协作体验（2026-10-27）

- 桌面端打开「问问 Health」后，从右侧展开**非模态**对话工作区。左侧原有导航、页面内容和数据操作继续可见、可点击；聊天面板独立滚动，不覆盖主页面，也没有全屏灰色遮罩。
- 用户浏览首页、身体、指标或某条健康问题时，聊天记录、输入中的草稿和打开状态保持不变。提问时会将当时的页面名称记录为演示上下文；后续换页只更新「当前页面」，不会重写之前的消息。
- 收起再打开，当前标签页中的演示会话仍在；刷新浏览器后恢复初始空会话。没有后台对话持久化，也没有连接真实 AI。
- 平板/窄屏使用下方非模态停靠区域，让页面和对话同时可见；移动端底部四 Tab 保持可操作。后续可根据实际 Preview 体验调整比例。
- 普通记录编辑、报告导入仍为临时模态抽屉；**桌面右侧抽屉使用直角边缘，移动端底部抽屉恢复顶部双圆角**，方便区分前后层。应用、账号与设置统一由 ALOHA Hub 菜单进入。
- 对话回车发送兼容中文输入法候选词确认；Shift+Enter 可换行。所有图标继续使用 Lucide。

## Token 体系

样式按三层组织，**没有复制一套独立的 ALOHA 主题**：

1. **跨 PWA 全局基础：** packages/design-tokens/tokens.css。全局颜色、字体、间距、圆角、阴影、控件及各领域 Accent 是唯一共享来源。
2. **Health 应用语义：** apps/health/src/tokens.css。以 --health-* 对应画布、卡片、文字、边线、强调色和控件角色；全部派生自 --aloha-*，不在页面重复写静态配色。
3. **界面实现：** apps/health/src/style.css 消费语义 Token，根据 Mobile / Tablet / Desktop 调整布局。图标统一使用 lucide-vue-next，不使用字符图标、Emoji 或自行画的替代图标。

共享 Token 新增要证明至少两个应用会复用；Health 特有语义留在本应用。
